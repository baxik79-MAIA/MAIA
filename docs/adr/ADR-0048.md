# ADR-0048: Exact non-network capability for Rust null stdin in Tier-1

Status: Accepted for M0.16.5; LAB host capability prepared; full production verifier qualification pending

Canonical contract: `spec/evolution_protected_runtime.yaml`
Related: `ops/evolution-process-host`,
`ops/evolution-workspace-host/tools/m0165-r5v`

## Context

The production process host captures root stdout and stderr with host-created
pipes and launches each root suspended in a unique zero-network AppContainer,
assigning it to the Job Object before resume. Cargo then starts `rustc` using
Rust `std::process::Command::output()`. On Windows, `Command::output()` opens
`\\.\NUL` for its default stdin before creating captured output pipes.

The production AppContainer probe showed that inherited stdio, Win32
`CreatePipe`, piped stdout/stderr, and all three pinned Rust 1.98.1
`child_pipe.rs` NT calls succeed. `CreateFileW("NUL", GENERIC_READ)` and
`Command::spawn` with `stdin = Stdio::null()` fail with Win32 5. The denial is
on null-device access, before captured-pipe setup.

## Decision

Each unique per-run AppContainer keeps its random package SID and receives
exactly one additional capability SID, derived from
`maia.evolution.tier1.null.stdin`. The host grants that SID one persistent,
non-inheritable `FILE_GENERIC_READ` ACE on `\\Device\Null`. The capability is
not placed on any filesystem, registry key, named pipe, or other object. No
network capability is allowed. The capability itself grants no network
authority and does not replace the per-run package SID used for temporary
filesystem ACLs.

Host preparation is a separate, repeatable administrator operation. The
ordinary runner only reads and verifies the exact ACE and fails closed if it
is absent or differs. The rollback command removes ACEs for this exact
capability SID while preserving unrelated current DACL entries. No NamedPipe
namespace ACL is changed.

## Verification requirements

- Before resume, the child token must be an AppContainer in the Job and its
  capability list must equal the single derived `maia.evolution.tier1.null.stdin`
  SID. This exact allowlist excludes known network capabilities and any
  unreviewed extra SID.
- The host must verify the device ACE has the exact read-only mask and no
  inheritance before it creates the AppContainer.
- The production probe must pass inherited stdio, Win32 `CreatePipe`, Rust
  `Command::spawn` variants, `Command::output()`, and each pinned NT pipe API.
- Production E4 still has to prove no network access and denied protected
  surfaces while the resource capability is present. Scratch zero-capability
  E4 evidence remains separate and does not establish production behavior.
- Per-run filesystem ACLs, profile deletion, process-tree cleanup, and the
  unique package SID remain required and must still be verified.

The production E4 probe also verified that the per-run package SID needs no
temporary ACE on the broad `C:\MAIA` ancestor. Removing that ancestor grant
keeps the read-only resource and candidate-target grants while avoiding ACL
propagation across unrelated host trees. The selected protected paths and
loopback denial remain part of the production isolation test.

## Consequences

The production token no longer has an empty capability list. Its exact
allowlist contains one narrowly scoped non-network resource capability; the
canonical boundary remains “without network capabilities.” Reports and tests
must distinguish this production profile from earlier zero-capability scratch
trials. Tier-1 remains unavailable until the administrator prepares the host
resource and the production probe and Cargo stages pass.
