# ADR-0028: Mutable external source freshness is a precondition

**Status:** Accepted — approval invalidation clause amended by ADR-0031
**Date:** 2026-09-11  
**Decision owner:** MAIA architecture

## Context
Delta/webhook delivery is at-least-once and can lag. A draft/reply planned against stale recipients or thread state must not execute merely because an older approval exists.

## Decision
Persist source version tokens and re-check mutable source state immediately before material side effects. Prefer strong connector preconditions when documented; otherwise re-fetch and compare. Version mismatch revokes stale approval and triggers re-plan.

## Amendment by ADR-0031 (MAIA 1.2.1)

The original decision above is preserved as history. [ADR-0031](ADR-0031.md) partially
amends only the sentence "Version mismatch revokes stale approval" with respect to
approval-state handling after source-version/payload divergence:

- `pending` / `approved` -> `revoked`;
- `not_required` / `rejected` / `expired` / `revoked` -> historical state preserved;
- all old bindings are invalid for the superseding payload/version.

The source-freshness precondition remains fully accepted. The state-aware mutation
policy in `spec/approval.yaml`, referenced by `spec/sync.yaml`, is canonical; the
new action/approval version is re-gated and may validly result in `not_required`.

## Alternatives considered
- Preserve the v1.1 implicit behavior.
- Let each connector/surface decide independently.

## Why alternatives were rejected
They make behavior ambiguous, unauditable, or unsafe across connectors.

## Consequences
Reduces stale-thread and recipient races.

## Security / privacy impact
Implementation must satisfy canonical security, approval, transport and compliance policy.

## Migration impact
This decision applies to v1.2+ implementations and supersedes contradictory v1.1 narrative assumptions.

## Amendment by ADR-0032 (MAIA 1.3.0)

Freshness evidence binds the exact Run and Action revision/hash and is never reused for retries. Unverifiable material freshness fails closed; compare-before-execute does not eliminate TOCTOU. Revision rebuild follows the new canonical build order. The ADR-0031 state-aware material-revocation exception remains in force. See [ADR-0032](ADR-0032.md) and the current canonical YAML.
