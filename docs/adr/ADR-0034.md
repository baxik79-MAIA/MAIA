# ADR-0034: authoritative local store and SQLite adapter

Status: Accepted by Architecture Desk for M0.3 implementation
Date: 2026-09-11

## Decision

M0.3 implements the persistence contract from ADR-0033 with two explicit
layers. `core/store` is an OS-neutral repository and transaction port crate
that depends only on `maia-domain` plus small serialization/hash utilities.
`infra/sqlite` is the local authoritative adapter and owns SQL, migrations,
SQLite pragmas, the authority lock, backup/recovery and adapter error mapping.

The store exposes separate repository traits for revisions, tasks, approvals,
runs, evidence and audit. T1–T5 operations are serialized SQLite immediate
transactions. Mutation and its audit append commit together or roll back
together. Current policy and actor authorization remain inputs from the upper
runtime; the store only revalidates persisted bindings and CAS facts.

The local profile uses one writable process per workspace, `foreign_keys=ON`,
WAL journaling and bounded busy handling. A second writable opener or lost
authority fails closed. SQLite critical identity, state, version, attempt,
binding and audit sequence/hash values are ordinary columns. Immutable complex
value objects may be stored as JSON.

M0.3 persists only execution and authority foundations: workspace metadata,
AgentTask, plan/action revisions, Approval, Run, freshness/reconciliation
evidence, policy snapshot references, audit records and the migration ledger.
Person, WorkGraph, Memory, message search, connectors, scheduler and UI remain
outside this milestone.

## Consequences

The public store crate cannot leak `rusqlite::Error` or filesystem details.
The adapter uses a bundled SQLite build for reproducible Windows linking and
keeps its dependency surface small. Full product composition remains a later
runtime concern: policy + orchestrator + store are composed above the
persistence layer.
