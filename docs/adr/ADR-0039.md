# ADR-0039: Business Outcome is separate from Run technical outcome certainty

Status: Accepted by Architecture Desk for M0.7

## Decision

Introduce Business Outcome as a new evidence-driven domain concept. It is not
the existing Run OutcomeCertainty value object and it does not alter Run,
reconciliation, retry or source-freshness semantics. An Outcome may refer to a
Task, Plan, Action, Run, Commitment, Project or another relevant subject, and
does not require a Run origin.

The lifecycle is candidate, observed, verified, rejected, disputed and
superseded. Observed requires source or evidence. Verified requires an explicit
verification method, sufficient evidence and retained provenance; model
confidence alone never verifies an Outcome. Supersession preserves history and
points to the newer Outcome.

## Consequences

Technical completion remains truthful without asserting business success.
Outcome measurement can use verified Outcomes while retaining competing or
later evidence, without weakening the existing execution FSM.
