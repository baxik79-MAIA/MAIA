# ADR-0045: M0.11 uses native eframe for the first MAIA desktop surface

**Status:** Accepted by M0.11 Architecture Desk directive

## Decision

Use `eframe` 0.31.1 for the first Windows MAIA desktop surface. It is a
Rust-native immediate-mode UI framework and does not require a web server,
browser runtime, cloud account or frontend package toolchain. UI code remains
an adapter over the existing Rust Core, SQLite adapter and loopback-only model
adapter.

## Commercial and security review

`eframe` 0.31.1 declares `MIT OR Apache-2.0`, supports commercial use under
either permissive license, and declares Rust 1.81 compatibility. It therefore
fits this repository's Rust 1.85 baseline. The currently published 0.36.x
line requires Rust 1.95 and is not selected. Source: [crates.io eframe
0.31.1](https://crates.io/crates/eframe/0.31.1) and the upstream
[eframe manifest](https://github.com/emilk/egui/blob/main/crates/eframe/Cargo.toml).

The initial dependency adds a native windowing/rendering surface, not a
listener or HTTP API. It adds no model/provider, connector, credential,
filesystem-crawling or execution capability. Default fonts are framework
assets only; M0.11 does not redistribute a third-party brand font or fetch
remote images.

## Consequences

The binary is Windows-runnable now and may remain cross-platform where eframe
supports it. M0.11 deliberately accepts an immediate-mode presentation layer
to keep the first real product path small; product semantics remain in Rust
backend ports and are never duplicated in UI state.
