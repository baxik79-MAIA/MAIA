# ADR-0037: bounded local immutable workspace evidence ingestion and citation semantics

Status: Proposed for Architecture Desk review — M0.6 Phase A

## Decision

M0.6 reuses the existing `Artifact` domain entity for a workspace-scoped,
immutable imported text snapshot. It does not create a separate semantic
document, source-blob, memory or WorkGraph entity. An Artifact of kind
`imported_text_evidence` owns the exact strict-UTF-8 snapshot text, SHA-256 of
the exact imported source bytes, byte length, media type, import-request
identity and private source provenance. The original external locator is not
a citation key.

The first input boundary is deliberately narrow: caller-supplied local regular
UTF-8 plain-text or Markdown files only. It rejects directories, recursive
discovery, UNC/network paths, links/reparse points, unsupported encodings and
over-bound input. One request admits at most eight files, each at most 262144
bytes and at most 1048576 bytes in total. No parser framework, connector,
model, network route or product-side effect is introduced.

The host acquires and validates every source before the authoritative T6
transaction begins. It reads each selected regular file through one opened
handle and revalidates identity and length; a detected source change fails the
whole request. T6 is atomic all-or-nothing: it either stores every immutable
snapshot and audit result or stores no artifact. The snapshot, not the later
external file, is read after restart.

Within one workspace, the same locator and same source bytes return the
existing Artifact and an idempotent audit result. Changed bytes at the same
locator create a new immutable Artifact, retaining the prior Artifact.
Different locators with equal bytes retain separate Artifact provenance while
sharing only workspace-scoped immutable content storage by SHA-256. Content is
never deduplicated across workspaces.

An `EvidenceCitation` identifies workspace, Artifact, snapshot hash and an
optional inclusive line range in the stored snapshot. It never exposes an
absolute local path as its canonical identity. The audit chain records minimal
artifact/request/provenance-hash references and outcomes; it never contains
snapshot text or a raw source locator.

## Boundaries

Imported evidence is not derived knowledge. M0.6 creates no `MemoryClaim`,
WorkGraph edge, commitment, decision, relationship fact, priority or inferred
semantic field. It is a durable record of selected bytes and provenance only.

The existing `Artifact` inventory is extended because it is the accepted
canonical concept for a durable artifact. A separate `SourceBlob` or
`ImportedDocument` entity would duplicate that concept and blur provenance
with the immutable MAIA-owned snapshot.

Deletion of an external source never deletes an Artifact. M0.6 adds no runtime
hard-delete API; later workspace erasure policy must preserve the existing
audit/tombstone rules.

## Consequences

The additive, required Artifact and import/citation contract is a canonical
minor-version evolution from MAIA 1.4.0 to 1.5.0. It requires generated domain
declarations and later domain/store/SQLite/runtime/host implementation after
Architecture Desk approves this Phase A diff.

No persistence implementation, migration, filesystem adapter, CLI, model
provider, Intelligence Fabric, connector, scheduler, UI framework or external
action is included in this Phase A decision.

## Alternatives rejected

- Persisting only a path and current hash, which fails after source change or
  deletion.
- Putting imported source text or raw paths into audit records.
- Treating evidence import as semantic interpretation or automatic memory.
- Partial per-file import results for this small bounded request.
- Cross-workspace content deduplication, which would weaken workspace privacy.
