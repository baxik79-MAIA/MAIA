# ADR-0031: Typed execution contracts and state-aware approval invalidation

**Status:** Accepted
**Date:** 2026-09-11
**Decision owner:** MAIA architecture

## Context
The field-name-only domain inventory does not specify wire types, nullability,
primitive constraints or state coupling. It is insufficient to generate production
contracts for AgentTask, ExecutionPlan, Action, Run and Approval without guessing.
Unconditional approval revocation also conflicts with truthful historical states:
only pending and approved have explicit transitions to revoked.

## Decision
Keep the existing entity inventory and add canonical primitives, value objects and
typed execution contracts in `spec/domain.yaml`. Internal IDs serialize as lowercase
hyphenated UUIDv7 strings and must eventually use distinct Rust strong newtypes.
PolicyId, ActorRef and OpaqueRef remain opaque non-empty UTF-8 strings without
semantic normalization; SurfaceId is an open registry. ActionType has lower-case
dot-separated syntax. Timestamps canonically serialize UTC with Z and exactly
millisecond precision. Version, Ordinal and Attempt use bounded unsigned integers.
Privacy, risk, gate and state enums reference their canonical sources; transitions
remain exclusively in `spec/states.yaml`.

CostEstimate uses unsigned integer millionths and a three-uppercase-ASCII-letter
currency code, never floating-point canonical money. Absence/null means no reliable
estimate; zero is a known estimate. Cost never authorizes execution or lowers risk.
RiskSummary is unique and ordered by canonical risk declaration order. Plan-level
approval_requirement uses GateType for the strongest gate under the evaluated policy
context. Both summaries are informational; each Action is independently evaluated.

SourcePrecondition contains external_id, source_version_token and
normalized_payload_hash. Connector context comes from Action.connector_profile_id,
which is required when source_preconditions is non-empty. No connector-specific
semantics enter the value object; mismatch handling references `spec/sync.yaml`.
Run executor identities are independently optional; actual/requested divergence
requires an explicit, visible, policy-compliant routing/fallback decision.

OutcomeCertainty is not_applicable for created/starting/running, unknown for
outcome_unknown/reconciling, and known for retryable_error/completed/failed/canceled.
Reconciliation changes unknown to known only when the outcome is sufficiently
resolved to leave reconciliation. This coupling adds no FSM transitions.

Material payload/action-hash or source-version divergence invalidates every old
approval binding for the new payload/version. Pending and approved transition to
revoked with reason action_hash_divergence. Not_required, rejected, expired and
revoked retain their historical states and cannot authorize the superseding version.
Recompute the action hash, create/increment the new action/approval version, resolve
risk and execute ApprovalGate again. The canonical gate_to_approval_state mapping
determines the result, including not_required without inventing a human approval.

This ADR partially supersedes/amends [ADR-0028](ADR-0028.md) **only** with respect to
approval-state handling after source-version/payload divergence. Its source-freshness
precondition remains fully accepted. The original decision text is retained with an
amendment notice. `spec/approval.yaml` and `spec/sync.yaml` are canonical; no new
ApprovalState transitions are introduced to preserve the old unconditional wording.
ADR-0024 compare-and-swap decisions and ExternalConflict behavior remain unchanged.

## Alternatives considered
- Infer production types and nullability from field names.
- Revoke every historical approval by adding convenient FSM transitions.
- Duplicate privacy/risk/gate/state enums in the domain contract.

These alternatives leave generator ambiguity, falsify audit history or cause drift.

## Consequences
Spec Guard fails closed on incomplete typed contracts, unresolved references,
incorrect certainty coupling and regressions to unconditional sync revocation.
Derived documentation is regenerated from YAML. Rust M0.1 can consume explicit
contracts after this specification-only M0.0.1 closure.

## Security / privacy impact
Old bindings never authorize changed payloads. Historical decisions remain truthful;
per-Action gating, freshness checks and the no-hidden-fallback invariant are preserved.

## Migration impact
MAIA 1.2.1 is a backward-compatible contract clarification. No runtime, database
migration or Rust workspace is introduced in this milestone.

## Amendment by ADR-0032 (MAIA 1.3.0)

Extended by Action/Plan immutable revisions, exact Run binding, ActionBindingV1 and separate Approval CAS version in MAIA 1.3.0. The original build-order sentence is superseded: finalize version, input, connector/tool binding and risk before computing action_hash, then evaluate policy and create a new binding unless denied. Expiry and policy validity are separate from history; material divergence still revokes pending/approved and preserves other historical states. See [ADR-0032](ADR-0032.md) and the current canonical YAML.
