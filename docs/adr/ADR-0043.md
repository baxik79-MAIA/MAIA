# ADR-0043: Route reasoning assurance before invoking participants

Status: Accepted

MAIA selects a reasoning assurance level through a provider-neutral router before any participant invocation. The router records its signals, policy floor, projected session cost and reason codes. It returns a non-executable orchestration plan for A0 through A4, or explicit `InsufficientAssurance` when the required path cannot be obtained.

A0 is deterministic. A1 requires one enabled participant. A2 requires a primary participant and a meaningfully independent verifier. A3 invokes the response-isolated Round Table. A4 adds recorded human acceptance of the reasoning conclusion. A4 acceptance does not authorize a side effect and does not replace ApprovalGate.

The participant registry is a provider-neutral capability seam: participant ID, provider, model reference, role capabilities, enabled state, supported assurance levels, cost metadata capability and availability health. It is not a provider adapter or a hidden fallback mechanism.

The router checks an estimated cost against the explicit session ceiling before reasoning. Unknown cost under a ceiling, budget exhaustion, unavailable participants, verifier failure, provider/quota/timeout failure, and adjudication failure are explicit insufficient-assurance outcomes. MAIA never silently drops an A2, A3 or A4 requirement to a lower assurance level. Risk classification and ApprovalGate remain independent.
