# M0.4 — Transactional Runtime Coordinator

`core/runtime` is the pure application layer connecting the accepted domain,
policy, orchestration and store contracts. It accepts resolved facts and
provides small command handlers for material Action revision, Approval
decision, Run preparation/transition and Task pause request.

Each handler evaluates the existing policy/orchestrator functions first and
then calls one atomic T1–T5 store operation. `prepare_run` cannot persist a
Run unless the resulting in-memory Run is `Created` and all authorization,
binding, routing, freshness and tool checks pass. No connector, scheduler,
filesystem, SQLite, UI or external side effect is present in this crate.

SQLite composition tests exercise allow, confirm, elevated assurance, stale
revision, freshness mismatch, pause race and unresolved reconciliation paths.
