# M0.5 — Executor Boundary & One-Shot Execution Driver

`core/executor` provides a single explicit execution path for a persisted
`Run(created)`. It revalidates the exact action/approval binding and supplied
policy, actor, freshness and routing facts; atomically claims the Run through
T4; enters `running`; invokes an injected `ActionExecutor`; and persists one
canonical outcome transition with audit.

The local outcome vocabulary is `EffectSucceeded`, `EffectFailedFinal`,
`EffectFailedRetryable` and `OutcomeUnknown`. Only the first three reach known
terminal Run states. `OutcomeUnknown` reaches `outcome_unknown` and must be
reconciled before any new attempt. A panic leaves the Run in an in-flight state;
`recover_incomplete_runs` is an observational helper with no automatic retry.

SQLite composition tests cover success, final and retryable failures, unknown
outcomes, interruption recovery, stale action/approval, task pause and
double-execute CAS protection. No connector, scheduler, persistence
implementation or external side effect is included.
