# M0.1.1: Execution binding and authorization contracts

Baseline: main at 049899f, MAIA 1.2.1. Target: MAIA 1.3.0.
Architecture authority: owner directive `MAIA_M0.1.1_Architecture_Directive_v1.md`,
recorded in ADR-0032 and canonical YAML. This milestone remains headless.

## Implementation boundary

The new action_binding/execution specs complement domain, approval, states and sync.
The generator reads them to emit domain declarations, canonical ordered enums and
structural predicates. Rust adds checked version/attempt successors, source duplicate
and connector selection checks, approval metadata checks and evidence shape checks.
Approval's structural transition method increments record version with overflow
protection; it does not implement atomic CAS or authorize human decisions. Complete
human-decision metadata is required for constructing an approved snapshot.

Domain objects cannot prove that a fingerprint is current, a source is authoritative,
an actor is authorized, or two actions imply the same side effect. Evidence contains
exact IDs/versions/hash so the future runtime can enforce those contracts. Optional
observations permit unverifiable evidence without pretending a match. Existing
read-only getters and private fields preserve the M0.1 construction boundary.

## Test strategy

`action_binding_vectors.json` contains fixed expected bytes and SHA-256 hashes.
Expected fixture bytes were constructed independently with Python for the fixture
subset (ASCII object keys, Unicode string values, null and safe integer ordinal).
The JS oracle uses the RFC8785 reference implementation. A UTF-8-vs-UTF-16 source
sorting case and adjacent versions above 2^53 catch cross-runtime drift. Schema
mutation is rejected; all other top-level binding fields have material-mutation
checks, while source array permutation intentionally preserves the hash.

`test_m011_contracts.py` contains test-only policy/CAS/retry snapshot oracles and
negative contract mutations. These are not reusable production authorization APIs.
The validator pins architecture obligations so edits weakening contracts fail closed.
Rust tests exercise actual constructors, immutability on failure, version overflow,
terminal retryable Runs, generated order/predicates and approval/evidence shape.

Acceptance A004/A011 and M018-M023 describe eventual runtime behavior. This milestone
establishes contracts and reference/structural coverage; it does not claim end-to-end
fulfillment of these acceptance criteria or real concurrent store testing.
