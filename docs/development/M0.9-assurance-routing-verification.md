# M0.9 assurance routing and orchestration verification

## Scope

M0.9 introduces `core/assurance-router`, a pure provider-neutral planning seam. It chooses the required A0–A4 assurance path from impact, ambiguity, uncertainty, evidence conflict, novelty, reversibility, explicit human escalation and a policy floor. It has no network, credential, persistence, action or ApprovalGate dependency.

`RoutingOutcome::Selected` contains a non-executable plan. `RoutingOutcome::InsufficientAssurance` retains the required level and explicit reason instead of silently falling back. A0 is deterministic; A1 requires a primary; A2 requires a primary plus independent verifier; A3 requires two Round Table members plus adjudicator; A4 requires the A3 capability path and separately recorded human reasoning acceptance.

## Known limits

The router plans and validates capability availability; provider invocation and measured-cost persistence remain adapter/store concerns. Cost stays unknown where a provider does not return it, and an explicit session ceiling converts that condition to `InsufficientAssurance` before reasoning.
