# M0.1.2 — Approval & Execution Conformance Hardening

Baseline: main at 472ff64e86e0bb3247aed41a7b1ea2927ba173d3, MAIA 1.3.0.
Target: MAIA 1.3.1. Scope: Architecture Desk accepted findings F1–F4 only.

Canonical changes precede domain changes. Run declares terminal_states; the generic
validator rejects outgoing edges from any declared terminal and pins the Run list.
The Approval snapshot compatibility matrix generates a structural Rust predicate.
Stored allow means not_required; a current allow can still authorize an approved
historical confirm snapshot. Current deny invalidates authorization without changing
the historical stored policy decision. These are distinct contexts.

Approved requires complete human metadata and the required approval assurance.
Rejected requires the same actor/time/surface attribution and at least confirm,
even for an elevated approval requirement. Pending has no decided actor/time/surface,
decision note or achieved human assurance. Structural transition_to cannot supply
human decision evidence; missing evidence fails without changing state/version.
Authoritative CAS and authentication remain future runtime responsibilities.

The snapshot CAS oracle validates binding/state/version, expiry, authorized actor,
policy/required assurance coherence, achieved assurance and decision metadata. It
uses authoritative now for decided_at, preserves immutable fields and fails without
mutating input snapshots. It does not claim actual store atomicity or concurrency.
Recipient completeness is checked before floors, including empty mail recipients
with destructive/privileged floors and valid private calendar events with no attendees.

Regression entry points: tests/spec/test_m012_hardening.py and Rust f2_f3/f3 tests.
Negative terminal mutations run the validator itself with in-memory YAML overrides;
they do not rely on generator drift. Run every edge destination against all four
terminal states, and reject weakened declarations. Run the full validation suite
listed in the M0.1.1 development note plus staged and post-commit whitespace checks.

No new architectural subsystem, third-party dependency or database migration.
M0.2 and all UI remain outside scope. Preserve 472ff64; use a separate milestone commit.
