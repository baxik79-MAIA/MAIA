# M0.2.1 — Persistence & Audit Contract Closure

This milestone closes the authoritative persistence and audit contracts before
any SQLite or repository implementation. The canonical source is
`spec/persistence.yaml` plus the new `spec/audit.yaml`; typed Task, Run and
AuditRecord fields remain generated from `spec/domain.yaml`.

The contract defines one mutable authority per workspace, immutable Plan and
Action revisions, Approval/Run exact bindings, mutable Task/Run CAS versions,
parent and uniqueness integrity, and the serialized T1–T5 authority
transactions. Human approval and later Run creation are deliberately separate
transactions.

Audit is a workspace-scoped append-only chain with atomically allocated
unsigned sequence, RFC8785-JCS SHA-256 record hashing and genesis zero hash.
Audit facts are privacy-minimized before append; credentials, tokens, message
bodies and full sensitive payloads are excluded by default.

The local profile promises an exclusive writable authority lock, fail-closed
lock loss, checksum-protected monotonic migrations, explicit offline restore,
backup-before-migration and injected application clocks. SQLite, FTS5,
`core/store`, `infra/sqlite`, persistence dependencies, connectors, scheduler
and UI remain deferred.

Validation includes Spec Guard, generated drift checks, Rust domain CAS/audit
tests and Python persistence/audit contract oracles.
