# Governance

MAIA is currently founder-led and actively developed. This document describes existing roles; it does not create a foundation, elected committee, support contract or new execution authority.

- The Founder retains authority for consequential business, legal, financial, licensing and irreversible decisions.
- The Architecture Owner resolves product direction, protected architecture boundaries and material unresolved technical disagreements.
- Maintainers review and integrate contributions within those boundaries and record decisions in canonical specifications and ADRs.
- Contributors propose focused changes with reproducible evidence. Independent technical review informs decisions and cannot bypass human action approval.

The canonical source order and dependency boundaries apply to community changes. Disagreements should identify the contract, alternatives, evidence and unresolved question without sharing private reasoning transcripts or operational data.

Public source availability does not authorize production use of customer data, commercial commitments, changes to protected surfaces or enabling evolution in deployed builds. Existing commercial gates remain applicable; funding/company governance never becomes a Task or Action state.

The public maintainer is baxik79-MAIA. GitHub private vulnerability reporting is the canonical security channel; enablement is a post-push repository setting. See [MAINTAINERS.md](MAINTAINERS.md).
